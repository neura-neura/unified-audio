# Known limitations

This file is a release gate, not a place to hide incomplete work. Items remain here until they have a linked test or a documented product decision.

- A selectable final virtual microphone still requires one separately installed virtual audio driver. The base application does not ship a first-party signed driver.
- Hardware smoke passed for Micro Ugreen Soundcard (KT USB Audio) → kHs Gain VST3 → mute → standard CABLE Input (VB-Audio Virtual Cable) with `MuteSettled=True`, exact `OutputPeak=0` and 0/0 XRuns. A prior Both run reached `MixerMode=2`/`SystemCaptureRunning=True`; the current acceptance runs Voice when the read-only Listen probe cannot resolve all consumers. An audible reference recording/Discord receiving-app confirmation is still manual. Engine state and commands now persist MMDevice IDs and resolve the current friendly name before JUCE opens the endpoint; JUCE's own name-based device selector remains the last limitation for two simultaneously active endpoints with an identical friendly name.
- VST3 behavior is plugin-dependent. The scanner isolates discovery and the shell restarts an unexpectedly exited host with serialized connection/backoff; three exits in 30 seconds open a circuit breaker. Identifying and quarantining the exact plug-in that crashes later inside the live processing callback remains open.
- Exclusive-mode audio is outside the base product. Shared low-latency mode is used to preserve coexistence with communications applications.
- Endpoint loopback, process-tree loopback, session discovery, per-app meter/gain, include/exclude policy, Voice/PC/Both and ducking are integrated. Process filtering is bounded to 32 simultaneously active process captures; excess active processes are logged rather than allocating inside the callback.
- The asynchronous voice bridge is bounded, zero-fills and reports XRuns. After raising only the mismatched-rate prebuffer to 100 ms, a 60-second 44.1→48 kHz run passed with 0 underruns/overruns. The required eight-hour soak remains manual.
- The OSD and overlay support topmost/no-activate behavior, a real filled-circle visual, opacity, scale, per-monitor relative placement, unlocked native move/resize, locked click-through, locate/monitor pickers, state visibility modes and fullscreen OSD exclusion. Mixed-DPI display reconnect, exclusive-fullscreen acceptance and physical click-through/opacity interaction remain manual.
- Toggle, PTT, push-to-mute and hybrid work with a configurable global keyboard or mouse binding. Live QA settled State True then False; the editor includes wildcard, passthrough and neutral/left/right modifier sides; physical hardware and long-duration hotkey matrix remain manual.
- Global input and profile input resolve a physical capture by stable ID or follow-default policy; profiles expose basic output-role selection. Multi-input fan-out, per-role capture mutation and several simultaneous physical microphones remain manual. External volume lock is implemented with a volume picker, but third-party fights and hardware acceptance remain open.
- An active profile is debounced and transactionally reapplied after its input/output IDs reconnect. Physical unplug/replug acceptance remains manual because it requires hardware intervention.
- Windows Core Audio exposes setting a role default but no supported operation for restoring a role to an originally unset state. Profile rollback therefore restores roles with captured device IDs and intentionally leaves originally unset roles untouched; it does not invent a “clear default” mutation.
- Program, PowerShell and optional Voicemeeter actions, linked profiles, normal auto-exit requests and AFK are implemented. Aura Sync remains open because no redistributable SDK/license boundary has been accepted.
- Update discovery requires a release-side SHA-256 file and deletes a mismatched download; /NCRC is forbidden. Authenticode signing still needs an external code-signing certificate, so production releases must not enable unattended installation until signing is configured. The Release script rejects framework-dependent output; the installed self-contained runtime passed without machine-wide x64 .NET 10. Final unsigned installer: 75,661,199 bytes, SHA-256 C2DBDD3537FF6FF2680B1285B2CE4111DEA0CE51C1426670F5452B965127138D.
- English, Spanish and Simplified Chinese catalogs and an explicit/system language selector exist. English all-page scanning plus Spanish/Chinese restart navigation and live-graph checks pass; large-text truncation and screen-reader pronunciation remain manual.
- Legacy import has preview/confirmation, source fingerprints and adapters for Audio Profiles, Mic Mix, AHK_MicMute and MicVST. AHK-specific hotkey expressions are intentionally left disabled for native re-entry; imported executable/script actions remain disabled until trusted.
- Factory reset is recoverable rather than irreversible: it moves the exact shell settings, engine state and plug-in cache files into a timestamped backup with a manifest, keeps logs, preserves the current Windows-startup choice, then exits. It never recursively removes an application-data directory.
- Aura Sync and Voicemeeter are optional adapters subject to installed vendor runtimes and license review.
- Windows Listen-to-device loop/consumer churn remains a manual gate: the read-only probe exposes endpoint IDs and consumer status and the guard refuses unresolved consumers rather than mutating Listen or closing another application. In this acceptance `enabled=0`, `unknown=3`, so Both/System Ugreen was safely blocked and Voice was retained. NVDA, fullscreen/borderless overlay, physical click-through/opacity, audible receiving-app confirmation and a genuinely clean standard-user account require manual Windows desktop acceptance. The installer has passed install/Voice smoke/guard/uninstall in the unique per-user QA directory UnifiedAudio-QA-LoopOverlay-20260816 on the development account.
